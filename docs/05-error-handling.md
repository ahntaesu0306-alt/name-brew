# 05. 오류 처리 지침

> 무엇이 잘못되든 사용자는 **무슨 일이 생겼는지, 무엇을 하면 되는지** 알 수 있어야 합니다.
> 아래 문구는 **글자 하나 바꾸지 않고** 그대로 씁니다.

---

## 1. 오류 코드표 (단 하나의 기준)

### 1.1 서버가 보내는 오류 (`lib/errors.js`의 `ERRORS`)

| code | HTTP | 언제 | 화면 문구 |
|---|---|---|---|
| `EMPTY_SURNAME` | 400 | 성이 비어 있음 | 성을 입력해 주세요. |
| `INVALID_SURNAME` | 400 | 한글 1~2글자가 아님 | 한글로 된 성 1~2글자만 입력할 수 있어요. |
| `INVALID_REQUEST` | 400 | JSON이 아님, `surname`이 문자열이 아님 | 요청 형식이 올바르지 않아요. 페이지를 새로고침한 뒤 다시 시도해 주세요. |
| `METHOD_NOT_ALLOWED` | 405 | POST가 아닌 요청 | 지원하지 않는 요청 방식이에요. |
| `RATE_LIMITED` | 429 | OpenAI 요청이 잠시 너무 많음 | 요청이 많아 잠시 쉬어 가는 중이에요. 30초 뒤 다시 시도해 주세요. |
| `QUOTA_EXCEEDED` | 503 | OpenAI 크레딧 소진 | 지금은 이름 짓기 서비스를 이용할 수 없어요. 관리자에게 문의해 주세요. |
| `SERVER_CONFIG` | 500 | API 키 없음/틀림, 모델 이름 오류 | 서비스 설정에 문제가 있어요. 관리자에게 문의해 주세요. |
| `TIMEOUT` | 504 | OpenAI가 15초 안에 답하지 않음 | 이름을 짓는 데 너무 오래 걸렸어요. 잠시 뒤 다시 시도해 주세요. |
| `AI_UNAVAILABLE` | 502 | OpenAI 연결 실패, OpenAI 서버 오류 | AI 서비스에 연결할 수 없어요. 잠시 뒤 다시 시도해 주세요. |
| `AI_INVALID_RESPONSE` | 502 | AI 답이 형식에 맞지 않음, 쓸 수 있는 이름이 5개 미만 | 알맞은 이름을 찾지 못했어요. 한 번 더 눌러 주세요. |
| `UNKNOWN` | 500 | 위에 해당하지 않는 모든 오류 | 알 수 없는 오류가 발생했어요. 잠시 뒤 다시 시도해 주세요. |

### 1.2 화면에서만 생기는 오류 (`public/app.js`의 `ERROR_MESSAGES`에 추가)

| code | 언제 | 화면 문구 |
|---|---|---|
| `NETWORK_ERROR` | 인터넷 끊김 등으로 `fetch` 실패 | 인터넷 연결을 확인한 뒤 다시 시도해 주세요. |
| `CLIENT_TIMEOUT` | 20초 동안 서버 응답 없음 | 응답이 너무 늦어요. 잠시 뒤 다시 시도해 주세요. |
| `INVALID_RESPONSE` | 서버 응답이 JSON이 아니거나 형식이 다름 | 결과를 읽을 수 없어요. 잠시 뒤 다시 시도해 주세요. |

- `ERROR_MESSAGES`에는 **1.1의 11개 + 1.2의 3개 = 14개**가 모두 들어갑니다.
- 서버에서 받은 `code`가 `ERROR_MESSAGES`에 없으면 `UNKNOWN` 문구를 씁니다.
- 화면에서 입력 검사가 실패해 서버로 보내지 않은 경우에도 `INVALID_SURNAME` 문구를 그대로 씁니다.

---

## 2. 오류 처리 원칙

1. **화면이 멈추지 않는다.** 어떤 오류든 `try/catch`로 잡아 `error` 상태로 바꿉니다.
2. **입력과 이전 결과를 지킨다.** 오류가 나도 입력한 성과 이미 나온 이름 카드는 지우지 않습니다.
3. **기술 용어를 보여주지 않는다.** `500`, `undefined`, `TypeError`, 영어 오류 원문을 화면에 띄우지 않습니다.
4. **같은 문구를 쓴다.** 서버와 화면 문구는 이 표와 같게 맞추고, 다르면 화면(`ERROR_MESSAGES`) 문구를 우선합니다.
5. **자동 재시도하지 않는다.** 사용자가 버튼을 다시 눌러야 다시 요청합니다.
6. **로그에 개인 내용 금지.** 서버 로그에는 오류 코드와 OpenAI 상태 번호만 남깁니다.

---

## 3. 완료 기준
- [ ] `lib/errors.js`에 1.1 표의 11개 코드가 HTTP 상태·문구까지 같게 있다.
- [ ] `public/app.js`의 `ERROR_MESSAGES`에 14개 코드가 문구까지 같게 있다.
- [ ] 어떤 오류 상황에서도 영어 오류 원문이나 숫자 상태 코드가 화면에 보이지 않는다.
- [ ] 오류 후에도 입력한 성과 이전 결과가 남아 있다.

## 4. 검증 방법 (오류를 일부러 만들어 보기)

| 만드는 방법 | 기대 |
|---|---|
| `ahn` 입력 | 버튼 비활성 + `INVALID_SURNAME` 안내, 요청 없음 |
| `.env`의 `OPENAI_API_KEY`를 지우고 `npm run dev` 재시작 → 이름 짓기 | `SERVER_CONFIG` |
| `.env`의 키를 `sk-wrong`으로 바꾸고 재시작 | `SERVER_CONFIG` |
| `.env`에 `OPENAI_MODEL=no-such-model` → 재시작 | `SERVER_CONFIG` |
| 결과가 나온 뒤 Network `Offline` → 다른 이름 보기 | `NETWORK_ERROR` + 이전 카드 유지 |
| `curl -i http://localhost:3000/api/generate` (GET) | 405, `METHOD_NOT_ALLOWED` |

> 검증이 끝나면 `.env`를 원래 키로 되돌리세요.
